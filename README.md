# RAG retrieval benchmark (SciFact)

Порівняння стратегій пошуку для RAG на датасеті [SciFact](https://github.com/beir-cellar/beir) (BEIR): BM25, dense, та гібридні варіанти з Reciprocal Rank Fusion (RRF).

## Retrievers

| Назва | Опис |
|---|---|
| `bm25_retriever` | Milvus BM25 (sparse-вектор, `english` analyzer) |
| `dense_retriever` | `bge-small-en-v1.5` (quantized, ONNX), HNSW, COSINE, dim 384 |
| `rrf_fusion_k{20,60,100}_depth100` | Власний RRF на рівні **документів**: top-100 документів із BM25 та dense зливаються за `1 / (k + rank)` |
| `milvus_hybrid_rrf60` | Вбудований hybrid search Milvus (dense + BM25, `RRFRanker(60)`) на рівні **чанків** |

Усі retrievers індексують однакові чанки: рекурсивний спліттер, 300 токенів, перекриття 50. Результат зводиться до рівня документів (береться найкращий чанк документа), метрики рахуються по документах.

## Методика

- Запити: тестовий набір SciFact (`qrels/test.tsv`), лише запити з розміткою.
- Метрики: nDCG@10, MRR@10, Recall@10, Recall@100.
- Латентність: p50 на один запит (embedding + пошук), після прогріву на перших 100 запитах. У звіті також є p95.

## Результати

| Retriever | nDCG@10 | MRR@10 | R@10 | R@100 | p50, мс |
|---|---|---|---|---|---|
| BM25 (english) | 0.685 | 0.652 | 0.808 | 0.901 | 8.0 |
| Dense | 0.709 | 0.677 | 0.836 | 0.950 | 23.5 |
| Milvus hybrid RRF60 | 0.702 | 0.670 | 0.828 | 0.962 | 24.3 |
| RRF doc-level, k=20 | **0.728** | **0.698** | **0.849** | 0.965 | 28.7 |
| RRF doc-level, k=60 | 0.724 | 0.697 | 0.835 | 0.965 | 24.9 |
| RRF doc-level, k=100 | 0.722 | 0.697 | 0.827 | 0.965 | 24.4 |

### Висновки

- Dense краще за BM25 по всіх метриках якості (+0.024 nDCG@10, +0.049 R@100), але ~3x повільніший (embedding запиту).
- Гібрид з RRF дає найкращу якість: k=20 — nDCG@10 0.728 проти 0.709 у dense. Менше `k` сильніше віддає перевагу верхнім рангам, тому R@10 і MRR зростають.
- Milvus hybrid (RRF60) не краще за dense за nDCG@10, але дає найвищий R@100 серед не-кастомних варіантів. Він зливає на рівні чанків і з іншою глибиною (`k*10` чанків), тому пряме порівняння з doc-level RRF не повністю чисте.
- Різниця між RRF k=20/60/100 мала (≤0.006 nDCG@10). Запитів лише ~300, тож без довірчих інтервалів вважати її значущою не варто.
- Латентність вимірювалась на одному запуску й одній машині; використовуйте як порядок величини.

## Запуск

Потрібні JDK 21 та Docker (Milvus піднімається через Testcontainers).

```bash
./gradlew run
```

Скрипт піднімає `milvusdb/milvus:v2.5.4`, індексує корпус для кожного retriever, прогріває та друкує `EvalReport` для кожного.

## Структура

- [App.java](app/src/main/java/org/example/App.java) — завантаження даних, retrievers, метрики, evaluator.
- `app/src/main/resources/dataset/scifact/` — корпус і запити (parquet), qrels (tsv).
